# helix-match oracle fixtures (format version 1)

These fixtures hold the reference behavior of the `match` command family. Expected results are produced by the **oracle**
(`native/oracle`, crate `mini-helix-match-oracle`), which builds the pinned, patched Helix source
(`native/upstream/helix`, revision `ba40e547426b0f9896c8bdc699a4ab11f2b37dbc`) and feeds key events to the real
`helix-term` `Application` (same `integration` feature and `TestBackend` that upstream's own `helix-term/tests` use).
Key dispatch (`EditorView` keymaps), the `match` command handlers, tree-sitter syntax, the packaged runtime and the `helix-vcs` diff
worker are all upstream code. The oracle does not depend on `native/match-helper`, the Task 1 feasibility adapter or any extension code, and
contains no re-implementation of a Helix algorithm. Expected results are never generated by extension code.

```
npm run test:match:oracle                 # build, verify identity, run all cases, compare, self-test
npm run test:match:oracle -- --update     # regenerate `expected` after a reviewed oracle/runtime change
npm run test:match:oracle -- --filter surround/mr --no-build --dump-actual /tmp/actual
```

Layout: `cases/<group>.json` (case files), `schema/case-file.schema.json`, `schema/result.schema.json` (JSON Schema draft-07;
the Rust side additionally rejects unknown input fields).

## Case file

`{ "schemaVersion": 1, "group": "...", "provenance": {...}, "cases": [ { "id", "description", "source", "tags", "input", "expected" } ] }`.
Case ids are unique as `group/id`. `source` names the spec section, Task 1 finding or oracle finding that motivated the case.
Tag `quirk` marks an intentional upstream quirk; `quirk-control` marks the control case for it.

### `input`

| Field | Meaning |
|---|---|
| `text` | Exact document text. Loaded in memory (no file load, no newline normalization, no implicit final newline). The oracle fails if the loaded text differs from `text`. |
| `eol` | `lf` (default) or `crlf`: the document line-ending preference (`default-line-ending` and the document's `line_ending`). Other endings need the `unicode-lines` feature, which the pinned reference does not enable. The text may still contain lone CR or mixed endings; it is loaded exactly. |
| `language` | Helix language id (`rust`, `markdown`, `toml`, ...). Absent/null: plaintext. The syntax tree is built from the final text (initial parse). |
| `selectionUnit` | `char` (default): offsets are Unicode scalar indices, as Helix uses. `utf16`: UTF-16 code units, as the extension wire protocol uses; an offset inside a surrogate pair is an oracle error. |
| `selections` | Input ranges `{anchor, head}` (gap endpoints, direction = anchor vs head). Default one cursor at 0. Upstream normalizes the set (minimum width 1, merging, ordering); the result is the `initial` snapshot, so the normalization itself is part of the reference. |
| `primary` | Index of the primary range in `selections` before normalization. |
| `mode` | `normal` (default) or `select`. |
| `steps` | Key strings in Helix notation (`parse_macro`): characters, `<esc>`, `<ret>`, `<lt>`, `<A-w>`, `<C-x>`, digits for counts. Keys of one step are dispatched together; the editor then runs to idle and a snapshot is recorded. **A step boundary is an observation point**: `["mr(", "["]` records the replacement preview after `mr(` and the final state after `[`. |
| `git` | `{head, path, trust, attributes?, config?}`: a throw-away Git repository is created with `head` committed at `path` (or untracked when `head` is null), the document is opened from it through the real `Editor::open` (upstream `helix-vcs` baseline lookup), then its text is replaced by `text` (an unsaved edit). `trust`: `trusted` or `untrusted` workspace passed to `WorkspaceTrust`. Async diff work is settled before every observation. Global/system Git configuration is disabled. Optional `attributes`: `.gitattributes` content written and staged before the baseline commit. Optional `config`: text appended to `.git/config` after init (for example `core.autocrlf`, or a repository-local `filter.*` driver whose effect depends on `trust`). |
| `failure` | Deterministic parser failure injection without replacing command orchestration. `{"kind":"initial-parse"}`: the document keeps its language but has no syntax tree (the state upstream leaves after a failed `Syntax::new`). `{"kind":"incremental-parse","afterStep":n}`: after step `n` the syntax tree is dropped (the state upstream leaves after a failed `Syntax::update` in `Document::apply`, never re-enabled). |
| `queryOverrides` | Real failure injection: `{language, file, content}` replaces one query file in a temporary overlay of the packaged runtime (grammar libraries and licenses are symlinked); the unchanged upstream query compilation fails. Examples: a broken `textobjects.scm` leaves syntax available but capture objects absent; a broken root `highlights.scm` makes syntax initialization fail. Cases using it record `oracle.runtimeOverlay: true`. |

### `expected` (result format)

See `schema/result.schema.json`. Summary: `reference` (identity), `oracle` (driver, test-only keymap override hash, overlay flag), `initial`
(snapshot before any key), `steps[]` (`keys`, `exited`, `snapshot`) and `final` (last snapshot). A snapshot holds:
`text`, `textUtf16Length`, `eol`, `selections[]` (`anchor`, `head`, `anchorUtf16`, `headUtf16`, `direction`), `primary`, `mode`, `count`
(pending editor count), `status` (`category`: none/hint/info/warning/error, exact upstream `message`), `autoinfoTitle` (the upstream key-help popup
title, e.g. `Match`, `Match inside`, `Replace with a pair of`, which identifies a pending input phase), `parser`
(`language`, `syntax`: none/available/unavailable, `layersAtPrimary`: injection layers containing the primary range) and `diff` (settled hunks).

Selections are in upstream order with the primary index into that order. Intermediate replacement selections after `mr<old>` have two points per original
range and primary index doubled, as upstream defines them. Commit outcome is the text/selection change of the step (the oracle has no
edit-commit protocol).

## Identity and provenance

Every result embeds the reference identity read from `native/helix-lock.json` (helix revision, archive, unpatched and patched source tree hashes, compatibility identity, upstream
`Cargo.lock` hash, toolchain, target, runtime hash, manifest hash). Before any case runs, `scripts/test-match-oracle.cjs` verifies the patched source tree stamp and re-hashes every
runtime asset against the lock; each oracle process re-checks the runtime manifest against the lock. A different runtime hash, source tree or compatibility identity fails the run
(also through the stored `expected.reference`), so expected results cannot silently outlive the reference they were generated from.

## Self-test (part of `npm run test:match:oracle`)

* a deliberately changed expected selection is reported as a mismatch;
* a test-only keymap override (`m i` mapped to `select_textobject_around`, `oracle --keymap-override`) makes `miw` produce the `maw` result: dispatch is real and a changed dispatch is detected;
* the upstream quirks are reproduced from the stored results (function ending exactly at EOF is a no-op for `mif`; with a final newline it is not);
* selected cases are deterministic on re-run;
* `cargo metadata` shows no path package other than `native/oracle` and `native/upstream/helix` (no production adapter, no feasibility crate);
* `native/oracle/Cargo.lock` has no version or checksum deviation from the pinned upstream `Cargo.lock`.

`--mutate expected` and `--mutate dispatch` are RED demonstrations: they apply the deliberate change to the whole suite, which must then fail.

## Extending

Later tasks add cases by appending to a group file (or adding a group file) with `input` only and running `--update`; review the diff of `expected`. Never hand-edit `expected`.
Known limits of this version: the oracle runs on unix hosts (the key event conversion uses `termina`; query overlays use symlinks); only `lf`/`crlf`; no `i`nsert mode scenarios beyond what a step
reaches; SELECT mode is available as an initial `mode` only for completeness (SELECT parity is out of scope).
