## How it works

* `native/oracle` (own Cargo workspace; crate `mini-helix-match-oracle`) depends only on the pinned, patched `native/upstream/helix` crates (`helix-term` with upstream's `integration` feature, `helix-view`, `helix-core`, `helix-loader`, `helix-vcs`) plus registry crates already in the pinned lock. It constructs the real `helix_term::application::Application` (TestBackend, same as upstream's `helix-term/tests`), replaces the buffer text/selection like upstream's harness, and feeds `termina` key events built with `helix_view::input::parse_macro` through `Application::event_loop_until_idle`. Dispatch is the upstream `EditorView` keymap; handlers are the upstream commands. No Helix algorithm is re-implemented.
* Packaged runtime root through the Task 2 patch (`helix_loader::initialize_packaged_runtime_root`), `HELIX_RUNTIME`/HOME/XDG/APPDATA/Git global config isolated per process. Language loader from the built-in `languages.toml`.
* One process per case (fresh tokio runtime); runner `scripts/test-match-oracle.cjs` transports JSON, compares, and self-tests. Before any case: patched source tree hash and every runtime asset are verified against `native/helix-lock.json` (the runner re-hashes 1799 assets and recomputes the runtime hash); each oracle process re-checks manifest vs lock and embeds the reference identity in the result.
* `HELIX_DISABLE_AUTO_GRAMMAR_BUILD=1` (runner env and `native/oracle/.cargo/config.toml`): `helix-term/build.rs` would otherwise fetch and compile all 301 grammars into `target/` (observed in the first builds: 3.6 GB, network). The oracle uses the verified packaged runtime instead; the flag changes no compiled Rust code.
* Format and extension guide: `test/fixtures/helix-match/README.md`; schemas `schema/case-file.schema.json`, `schema/result.schema.json`.

## Quirks confirmed in the real helix-term (stored as fixtures, tag `quirk`)

1. A function ending exactly at EOF (no final newline) is a no-op for `mif` and `maf` (`syntax-objects/quirk-mif-function-ends-at-eof`, `quirk-maf-...`); the same function followed by a newline selects the body (`quirk-control-mif-with-final-newline`). Confirms the Task 1 finding.
2. With the cursor inside an injected `comment` layer (text after `//`), `mic` and `mac` are no-ops in Rust; on the comment marker (root layer) `mic` selects the comment (`quirk-mic-inside-comment-injection`, `quirk-mac-...`, `rust-mic-comment-marker`). New finding, same mechanism as injected objects (smallest layer decides).

Other recorded reference facts worth Task 7-16 attention: upstream normalizes a point selection to a 1-wide range (`initial` snapshot); `ms<C-x>`/`mi<A-w>` read the character of a modified key (so `ms<C-x>` adds `x`); `mi(` with the cursor after a string literal inside call arguments is a no-op while `mim` finds the pair; a broken injected-language `highlights.scm` still lists the injected layer at the primary range (`parser.layersAtPrimary`) while capture objects are no-ops (Task 9 must compare layer membership against the reference, not assume removal); `2m3i{` beyond the nesting depth is a silent no-op; an error status raised by `mr(` is cleared by the replayed `d` (observable only with step boundaries).

## Parser failure injection

`failure.initial-parse` / `incremental-parse` set `Document.syntax = None`, exactly the state upstream's `set_language` and `Document::apply` leave after a failed `Syntax::new`/`Syntax::update` (500 ms timeout failures themselves are not reproduced; spec excludes timing races). `queryOverrides` provide real compile-failure injection through a temporary runtime overlay (symlinked grammars, copied queries). Command orchestration is never replaced.

The oracle binary's dep-info lists no file from `native/match-helper` or `native/feasibility`. The runner re-checks this with `cargo metadata` on every run.

(The scratch build also compiled all grammars through helix-term's build.rs, before the env flag existed; the oracle code is identical.)

## Deviations and notes

1. `native/oracle/Cargo.lock` seeded by copying the pinned upstream `Cargo.lock` and letting cargo prune: 315 of 337 pairs kept (314 identical to upstream + path package `mini-helix-match-oracle`), 23 pruned, **0 deviations**, SHA-256 `9e7b2a73...e900f3`. `native/runtime/compare-cargo-lock.cjs` is hard-wired to `native/Cargo.lock`, so the runner contains its own equivalent comparison; same rules.
2. Direct `cargo build` from the repository root without `HELIX_DISABLE_AUTO_GRAMMAR_BUILD=1` works but fetches and builds grammars (network); the runner and `native/oracle/.cargo/config.toml` (effective when cwd is `native/oracle`) set it. The log was captured with the variable set.
3. `selections` default unit is Unicode scalar indices; every snapshot also carries UTF-16 projections. Input in UTF-16 is supported (`selectionUnit: utf16`; surrogate-interior offsets are rejected).
4. Eol preference: `lf`/`crlf` only (the pinned reference is built without `unicode-lines`, so no other `default-line-ending` can be configured). The text itself is loaded exactly: lone CR and mixed EOL text are represented and covered by fixtures (`selections-eol/lone-cr-mip`, `selections-eol/crlf-pref-lone-cr-mi-paren`; see Correction).
5. Unix only (termina key events, symlink overlay). Windows/macOS oracle runs are not exercised (spec runs the oracle on the development host).
6. Commit outcome is represented by the step's text/selection change; the oracle has no commit protocol. Freshness/stale-edit checks are adapter concerns (Tasks 4-6).
7. `helix-loader` emits the Task 2 `unused import: path` warning (cosmetic).
8. Wall-clock timeout behavior, SELECT-mode parity, registers, macros are out of scope (spec).

## Correction (task #36: P3R-1, P3R-2, P3R-3)

Evidence: `correction/*.txt`. Case count is now 113 (106 original + 7 new). The 106 original `input` and `expected` blocks are unchanged (`correction/expected-unchanged.txt`, compared against the post-task04 snapshot).

* **P3R-1 (diff settle with converted baseline).** `settle_diff` no longer compares the diff base length with the raw fixture HEAD. The expected base is obtained through the same upstream calls `Editor::open` makes (`diff_providers.get_diff_base`, decoded with `helix_view::document::from_reader` and the document encoding, so a UTF-8 BOM is stripped) and the observation waits until the published diff has that base and the current document text. helix-vcs publishes base, document and hunks together under one write lock, so this is deterministic and cannot observe a half-updated diff; comparing the base as well keeps a freshly created handle (which publishes nothing until its first run) from looking settled. New case `git-hunks/mig-bom-baseline` (`baseChars` 6, one hunk, `mig` selects `B\n`) settles and reproduces on 4 consecutive runs (`correction/bom-repeat.txt`). No CRLF-converted baseline case was added: it needs repository attributes or filter configuration, which the schema does not carry (the existing `mig-crlf-head` case covers a CRLF baseline without conversion).
* **P3R-2 (excluded grammars).** The "produced no syntax tree" guard is kept but skipped when the document language's grammar (`grammar`, defaulting to the language id) is listed in the runtime manifest's `excludedGrammars` (wren, gemini). Such results record `parser.syntax: "unavailable"`. New cases `syntax-objects/excluded-wren-miw`, `excluded-wren-mif-absent`, `excluded-gemini-miw`, `excluded-gemini-mif-absent` (miw works; mif is a no-op).
* **P3R-3 (EOL wording and coverage).** Deviation note 4 above is corrected; only the `eol` preference is limited to lf/crlf. New cases `selections-eol/lone-cr-mip` (`"ab\rcd\nef\r\ngh\n"`, mip selects [0,13]) and `selections-eol/crlf-pref-lone-cr-mi-paren` (`"x (a\rb) y\r\n"`, crlf preference, mi( selects [3,6]); expected values generated by the oracle.
