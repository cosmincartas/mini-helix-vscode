## Problem

Mini Helix has `mi`, `ma`, and `mr` from Helix's match menu, but not `ms`
or `md`. **[repo]**
- `m s` and `m d` are bound to `miniHelix.noop`. Pressing them cancels the
  chord and types nothing. **[repo]** (`package.json`, generated by
  `scripts/keybindings.cjs`)
- The README lists this as a known gap: "There are no `mm`, `ms`, or `md`
  commands". **[repo]** (`README.md`, Limitations)
- The match spec put them out of scope. **[repo]**
  (`docs/context-engineering/helix-match-typescript/spec.md`, Out of scope)

The user wants the two missing surround commands, and wants them to match
Helix as much as possible. **[user]**
- `ms<char>` wraps each selection in the pair for `<char>`.
  `ms(` on `text` gives `(text)`.
- `md<char>` removes the enclosing `<char>` pair around each cursor.
  `md(` on `(text)` gives `text`.

`mm` (go to the matching bracket) was first in the request. The user then
removed it from scope. **[user]**

## Definition of done

### `ms` (surround add)

1. `ms<char>` puts the opening character before each selection and the
   closing character after it, in NORMAL mode. **[user]** **[helix]**
2. **Any printable character works.** A bracket gives its pair, and a
   closing bracket is an alias: `ms(` and `ms)` both give `(text)`. Any
   other character is used on both sides: `ms*` gives `*text*`.
   **[helix]** (`get_pair`) Mini Helix's `replacementPair` already does
   this for `mr`. **[repo]**
3. **`ms` then Enter** puts a line break before and after each selection.
   It uses the document's line ending. **[user]** **[helix]**
4. **After `ms`, each selection grows to include the new delimiters.** Its
   direction stays the same. **[helix]** (`surround_add` builds each new
   range from `from` to `to + 2`, or `to` + two line endings for Enter.)
5. **A count does nothing.** `3ms(` adds one pair, not three.
   **[helix]** (`surround_add` never reads the count.) The count is still
   cleared. **[proposed]**
6. **Any other key cancels.** Escape, or a key that types no character,
   ends the command with no edit. **[helix]** (`None => return`)

### `md` (surround delete)

7. `md<char>` deletes the enclosing `<char>` pair around every cursor.
   **[user]** **[helix]**
8. **`md` finds pairs the same way `mr` does today.** **[user]** That means:
   - Only the 11 delimiters work: `'` `"` `` ` `` `(` `)` `[` `]` `{` `}`
     `<` `>`. A closing character is an alias. **[repo]**
   - Brackets are matched over the whole document, with nesting. **[repo]**
   - Quotes pair up left to right within one line, and escaped quotes are
     skipped. **[repo]**
   - These rules differ from pinned Helix. See Constraints.
9. **A count picks the n-th enclosing pair.** With the cursor on `b` in
   `(a (b))`, `2md(` gives `a (b)`. **[user]** **[helix]** With quotes, a count of 2 or more finds
   nothing, as with `mr` today. **[repo]**
10. **All or nothing.** If any cursor has no pair, or one delimiter would
    belong to two different pairs, nothing changes. **[helix]**
    (`get_surround_pos` fails for the whole selection set.) `mr` already
    works this way. **[repo]** (`replaceSurround`)
11. **The selections stay where they are.** They only shift to follow the
    deleted characters. **[helix]** (`surround_delete` sets no new
    selection.)

### Both commands

12. Each successful `ms` or `md` is one undo step and one `u` revision, as
    `mr` is today. **[proposed]** (follows `mr`, see `README.md`)
13. Escape or an invalid key after `m s` or `m d` cancels the command,
    clears the count, and types nothing. **[proposed]** (follows `mr`)
14. The README is updated:
    - the match key table gets rows for `ms` and `md`
    - the Limitations line about `ms` and `md` is reworded so that only
      `mm` is listed as missing
    - every remaining difference from Helix is listed (see Constraints)
    **[user]** **[repo]**
15. `npm test` and `npm run test:integration` pass. The keybinding check
    compares `package.json` to `scripts/keybindings.cjs`. **[repo]**

## Affected users and systems

- **Users:** people who use Mini Helix in NORMAL mode. `ms` and `md` stop
  doing nothing and start editing text. **[repo]**
- **Keybindings:** `scripts/keybindings.cjs` and the generated
  `package.json`. **[repo]**
  - `m d <delimiter>` becomes a chord, like `m r <delimiter>`. **[proposed]**
  - `m s` must wait for one more key that can be any printable character
    or Enter. **[helix]**
- **Waiting for a key:** today only `mr<old>` waits for a key. It uses the
  `miniHelix.surroundReplacePending` context key and the `Match` controller
  in `src/vscode/match.ts`. **[repo]** `ms` needs the same kind of waiting
  state. **[proposed]**
- **Enter:** in today's waiting state, Enter cancels. **[repo]**
  (`enter` → `miniHelix.cancelSurroundReplace`) After `ms`, Enter must mean
  "wrap in line breaks" instead. **[user]** After `mr<old>`, Enter keeps
  cancelling, as in Helix. **[helix]** (`surround_replace` takes only
  characters.)
- **Core matching:** `src/core/match.ts` already has `findPair`,
  `delimiterPair`, `replacementPair`, and the all-or-nothing check in
  `replaceSurround`. **[repo]**
- **Undo history:** `src/core/history.ts` and the `u`/`U` commands, which
  `mr` already uses. **[repo]**
- **Read-only editors:** `mr` is a no-op there. **[repo]** `ms` and `md`
  should follow the same rule. **[proposed]**

## Constraints

- **Match pinned Helix as much as possible**, and list every gap in the
  README. **[user]**
- **`md` uses today's `mr` pair rules**, not Helix's. **[user]** This keeps
  `md` and `mr` consistent. It leaves these known gaps, which the README
  must list. **[helix]**
  - Helix finds the nearest quote before the cursor and the nearest one
    after it, across lines, with no escape handling. Mini Helix pairs
    quotes within one line.
  - Helix accepts any character, for example `md*` on `*x*`. Mini Helix
    accepts only the 11 delimiters.
  - Helix uses `m` for "the nearest pair of any bracket kind". Mini Helix
    does not.
  - Helix also knows `‘’`, `“”`, `«»`, `「」`, `（）`, and `||` as pairs.
  - The same gaps already apply to `mi`, `ma`, and `mr` today. Aligning
    them is not part of this work. **[user]**
- **`mm` is out of scope.** **[user]**
- **No parser and no tree-sitter.** Matching is plain text scanning, as for
  `mi`/`ma`/`mr`. **[repo]** (`README.md`; `helix-match-typescript/spec.md`)
  The reference is Helix's plain-text path, which Helix uses when a file
  has no syntax tree. **[helix]**
- **The keybindings are generated.** `npm test` fails if `package.json`
  and `scripts/keybindings.cjs` drift apart. **[repo]**
- **US keyboard layout** is the layout the project tests against. **[repo]**
  So `ms` accepts only characters that the generated bindings can type.
  **[repo]** (`typedCharacters`)
- **Mixed-in changes:** the working tree has other uncommitted work:
  - backtick (`` ` ``) text objects, in `scripts/keybindings.cjs`,
    `package.json`, `src/core/match.ts`, `README.md`, and the match tests
  - an untracked intent for `o`/`O` in `docs/context-engineering/open-line/`

  This change touches the same match files. **[repo]**

## Open questions

1. **`ms` on an empty selection:** a Helix selection always covers at least
   one character. In Mini Helix, an empty selection stands for Helix's block
   cursor and covers the character under it, as for `d`. **[repo]**
   (`README.md`; `src/core/editing.ts`)
   **[proposed]**: `ms(` on a cursor wraps the character under it, so
   `a|bc` gives `a(b)c` with `(b)` selected.
   - **[unknown]**: what happens at the very end of the text, where there
     is no character under the cursor.
   - Consequence: the expected text and selections in the `ms` tests.
2. **Error message for `md`:** Helix shows an error in the status line when
   no pair is found or two cursors share a delimiter. **[helix]** `mr` in
   Mini Helix makes no edit and shows no message. **[repo]**
   (`src/vscode/match.ts` reports nothing.)
   - **[unknown]**: should `md` show a message, as Helix does, or stay
     silent, like `mr`?
   - Consequence: if `md` shows a message, `mr` should probably show one
     too, so the two stay consistent.
3. **Checking against Helix:** for `x`/`X`, the project runs an oracle
   against pinned Helix (`scripts/helix-line-oracle.cjs`). **[repo]**
   Should `ms` and `md` get the same kind of check?
   - **[unknown]**. The user did not say.
   - Consequence: how much test work the plan contains.
